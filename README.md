# 🔥 Owen Bot

**Telegram-бот для [OwenCloud](https://web.owencloud.ru/): уведомления о событиях приборов ОВЕН,
текущие параметры и удалённое управление — прямо в Telegram.**

## Зачем

OwenCloud умеет рассылать уведомления о событиях, но доставка в Telegram работает не везде.
Owen Bot сам забирает журнал событий через [API OwenCloud](https://api.owencloud.ru/)
и присылает понятные сообщения о **начале и окончании** каждого выбранного события.

## Возможности

- 🔔 **Уведомления о начале и окончании событий** — с длительностью и временем в часовом поясе прибора.
- ⚙️ **Выбор событий** по каждому прибору: «только аварии», «все» или конкретный список.
- ☑️ **Отметка прочитанными** — кнопкой под уведомлением или разом, командой «Прочитать все».
- 📊 **Текущие параметры** прибора, сгруппированные по категориям OwenCloud.
- 🎛 **Управление** — запись управляемых параметров с подтверждением и отслеживанием статуса команды.
- 🔑 **Несколько аккаунтов OwenCloud** в одном чате; ключи хранятся **зашифрованными**.
- 🔒 **Закрытый режим** — доступ к боту только по коду.
- 👥 Работает в личных и групповых чатах.
- 🌐 Прокси SOCKS5/SOCKS4/HTTP для Telegram, в том числе с логином и паролем.
- 🔁 Повтор запросов при обрывах связи с Telegram и OwenCloud.

## Как выглядят уведомления

```
🔴 Котельная — авария
Не удалось поджечь
🕒 20.02.2026 14:53
                     [ ✔ Прочитано ]
```
```
✅ Котельная — авария завершена
Не удалось поджечь
🕒 14:53 → 15:09 (16 мин)
```
```
🔵 Котельная
Котельная в режиме поджига
🕒 20.02.2026 14:55
```

| Значок | Что означает |
|:-:|---|
| 🔴 / ✅ | начало / окончание аварийного события |
| 🔵 / ⚪ | начало / окончание информационного события |

Если в чате подключено несколько аккаунтов, в заголовке добавляется название компании.
Значения параметров показываются, только когда они что-то добавляют к названию события
(например, температура при «Перегреве»).

## Быстрый старт

### 1. Что понадобится

- Linux-сервер с Docker и Docker Compose;
- токен бота от [@BotFather](https://t.me/BotFather);
- API-ключ OwenCloud (профиль пользователя в OwenCloud → API-ключ) — его каждый пользователь
  добавляет в боте сам.

### 2. Установка

Готовый образ лежит на Docker Hub — [`whitemanprk/owen_bot`](https://hub.docker.com/r/whitemanprk/owen_bot),
на сервере нужны только `docker-compose.yml` и `.env`:

```bash
sudo mkdir -p /opt/owenbot && cd /opt/owenbot
sudo curl -fsSLO https://raw.githubusercontent.com/WhiteManPrk/Owen_Bot/main/docker-compose.yml
sudo curl -fsSL -o .env https://raw.githubusercontent.com/WhiteManPrk/Owen_Bot/main/.env.example
sudo chmod 600 .env
```

Сгенерируйте ключ шифрования и пароль БД:

```bash
sudo docker run --rm whitemanprk/owen_bot python -c \
  "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
openssl rand -hex 24
```

Заполните `.env` (см. [настройки](#настройки)) и запустите:

```bash
sudo docker compose up -d
sudo docker compose logs -f bot
```

Обновление до новой версии образа:

```bash
cd /opt/owenbot && sudo docker compose pull && sudo docker compose up -d
```

### 3. Начало работы

1. Откройте бота в Telegram и нажмите **Start** (если задан `ACCESS_CODE` — отправьте код).
2. Отправьте API-ключ OwenCloud — бот проверит его и сразу удалит сообщение с ключом из чата.
3. **Меню → /devices** → выберите прибор → **🔔 Включить уведомления** → при желании **⚙️ Выбор событий**.

## Настройки

Все настройки задаются переменными окружения в `.env` рядом с `docker-compose.yml`.

| Переменная | Обязательна | По умолчанию | Описание |
|---|:-:|---|---|
| `BOT_TOKEN` | ✅ | — | Токен бота от @BotFather |
| `ENCRYPTION_KEY` | ✅ | — | Ключ Fernet для шифрования API-ключей OwenCloud |
| `POSTGRES_PASSWORD` | ✅ | — | Пароль PostgreSQL |
| `ACCESS_CODE` | | *пусто* | Код доступа. Пусто — бот открыт для всех |
| `TG_PROXY` | | *пусто* | Прокси для Telegram: `socks5://`, `socks4://`, `http://` + `host:port` |
| `TG_PROXY_LOGIN` / `TG_PROXY_PASSWORD` | | *пусто* | Логин и пароль прокси, если он с авторизацией |
| `POLL_INTERVAL` | | `60` | Интервал опроса журнала событий, секунды |
| `OWEN_API_URL` | | `https://api.owencloud.ru/v1` | Адрес API OwenCloud |
| `OWEN_PROXY` | | *пусто* | Прокси для OwenCloud (обычно не нужен): `socks5://`, `socks5h://`, `http://`, `https://` |
| `OWEN_PROXY_LOGIN` / `OWEN_PROXY_PASSWORD` | | *пусто* | Логин и пароль прокси OwenCloud |
| `POSTGRES_DB` / `POSTGRES_USER` | | `owenbot` | Имя БД и пользователя |
| `LOG_LEVEL` | | `INFO` | Уровень логирования: `DEBUG`, `INFO`, `WARNING`, `ERROR` |

> [!IMPORTANT]
> Не теряйте `ENCRYPTION_KEY`: без него сохранённые API-ключи не расшифровать,
> и пользователям придётся добавить их заново.

### Закрытый режим

Если задан `ACCESS_CODE`, бот в каждом новом чате попросит ввести код. Сообщение с кодом удаляется,
после 5 неверных попыток ввод блокируется на 15 минут. При смене кода все чаты должны ввести новый —
до этого уведомления в них не отправляются.

### Логи

Бот пишет лог в `/logs/owenbot.log` внутри контейнера (стандартная ротация: 5 файлов по 10 МБ)
и в `docker compose logs -f bot` (3 файла по 10 МБ). Чтобы вынести логи на сервер,
раскомментируйте в `docker-compose.yml` строки `volumes: - ./logs:/logs` — файлы появятся в `./logs`.

## Команды бота

Команды доступны через кнопку **«Меню»** слева от поля ввода. Постоянной клавиатуры внизу нет —
она мешает жесту «назад» на Android.

| Команда | Действие |
|---|---|
| `/start` | Начало работы, справка |
| `/devices` | Список приборов со статусом |
| `/readall` | Отметить прочитанными все события по приборам с уведомлениями |
| `/accounts` | Добавить или удалить API-ключ OwenCloud |
| `/cancel` | Отменить ввод |

Статусы приборов: 🔴 авария · 🟠 непрочитанные аварии · 🟢 на связи · ⚫ нет связи · 🔔 уведомления включены.

## Как это работает

```
┌──────────────┐  журнал событий   ┌──────────────────────────┐   сообщения   ┌──────────┐
│  OwenCloud   │ ◄──────────────── │          bot             │ ────────────► │ Telegram │
│     API      │   раз в 60 с      │  поллер  +  aiogram-бот  │  (через прокси)└──────────┘
└──────────────┘                   └────────────┬─────────────┘
                                                │
                                        ┌───────▼───────┐
                                        │  PostgreSQL   │  ключи (зашифрованы), подписки,
                                        └───────────────┘  состояние журнала
```

- Поллер раз в `POLL_INTERVAL` секунд читает журнал событий каждого прибора, на который есть подписка,
  с перекрытием в 1 час — чтобы не потерять записи, попавшие в журнал с опозданием.
- Каждая запись журнала обрабатывается один раз: уведомления не дублируются, в том числе после перезапуска.
- При первом опросе прибора (или после паузы больше 6 часов) старые события не рассылаются.
- Если OwenCloud отклонил ключ, пользователь получает сообщение, а опрос по этому ключу останавливается.

## Безопасность

- API-ключи OwenCloud хранятся в БД зашифрованными (Fernet: AES-128-CBC + HMAC-SHA256).
- Сообщения с ключом и кодом доступа бот удаляет из чата.
- PostgreSQL не публикует порт наружу — доступен только контейнеру бота.
- Бот не открывает входящих портов (long polling).
- Управление выполняется от имени пользователя OwenCloud, которому принадлежит ключ,
  и только после подтверждения. В групповом чате управлять может любой участник —
  учитывайте это, добавляя ключ с правами на управление.

## Разработка

```
app/
  main.py         запуск бота и поллера
  config.py       переменные окружения
  owen.py         клиент OwenCloud API
  db.py           PostgreSQL: схема и запросы
  crypto.py       шифрование API-ключей
  services.py     кэш справочников OwenCloud
  poller.py       опрос журнала, начало/окончание событий
  notifier.py     отправка с учётом лимитов Telegram
  formatting.py   тексты уведомлений и параметров
  keyboards.py    общие клавиатуры
  bot/            обработчики: доступ, аккаунты, приборы, управление, прочтение
tests/            тесты (PostgreSQL + заглушки OwenCloud и Telegram)
```

Тесты запускаются в Docker вместе с временным PostgreSQL; к OwenCloud и Telegram не обращаются:

```bash
docker compose -f docker-compose.test.yml run --rm --build tests
```

### Сборка и публикация образа

Образ собирается из `Dockerfile` в корне репозитория и публикуется на Docker Hub с двумя тегами:
номер версии и `latest` (на него ссылается `docker-compose.yml`).

```bash
docker login                     # один раз, аккаунт whitemanprk
VERSION=1.0.0
docker build --platform linux/amd64 \
  --build-arg VERSION=$VERSION \
  -t whitemanprk/owen_bot:$VERSION -t whitemanprk/owen_bot:latest .
docker push whitemanprk/owen_bot:$VERSION
docker push whitemanprk/owen_bot:latest
```

Затем на сервере: `docker compose pull && docker compose up -d`. Чтобы закрепить конкретную версию,
укажите её вместо `latest` в `image:` в `docker-compose.yml`.
